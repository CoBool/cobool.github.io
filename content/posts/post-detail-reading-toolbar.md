블로그 글 상세 화면은 목록 화면보다 더 조심스럽게 설계해야 합니다. 사용자는 제목을 확인하고, 본문을 읽고, 필요한 순간에 목차나 이전 글로 이동합니다. 이 흐름에 맞지 않는 도구는 아무리 기능적으로 좋아도 읽기 경험을 방해합니다.

True Log는 기본적으로 `sidebar + main` 구조를 유지합니다. 따라서 글 상세에서만 세 번째 칼럼을 갑자기 추가할지, 아니면 목차를 읽기 도구로 다룰지 결정해야 합니다.

## 레이아웃의 기본 전제

큰 화면에서는 sidebar가 왼쪽에 고정되고, 작은 화면에서는 sidebar가 상단 흐름으로 이동합니다. 이 차이 때문에 모든 breakpoint에서 같은 TOC 배치를 강제하기 어렵습니다.

### 큰 화면의 장점

큰 화면에서는 가로 공간이 충분하기 때문에 목차를 계속 노출해도 본문을 크게 해치지 않습니다. 특히 긴 글에서는 목차가 현재 위치를 파악하는 보조 지도처럼 작동합니다.

```txt
desktop:
sidebar | article | toc
```

하지만 오른쪽 TOC가 너무 무거우면 글 상세가 문서 도구처럼 보일 수 있습니다. vCard 감성을 유지하려면 TOC는 주 콘텐츠가 아니라 조용한 보조 패널이어야 합니다.

### 작은 화면의 제약

작은 화면에서는 sidebar가 상단에 있으므로 sticky 요소를 추가할 때 더 신중해야 합니다. 화면 위쪽이 빠르게 복잡해지고, 본문이 밀리는 느낌이 생길 수 있습니다.

작은 화면에서는 목차를 항상 보이게 하기보다 필요한 순간에 호출하는 편이 낫습니다.

## TOC를 오른쪽에 두는 방식

오른쪽 TOC는 전통적인 기술 블로그와 문서 사이트에서 익숙한 방식입니다. Chirpy도 넓은 화면에서는 이 구조를 적극적으로 사용합니다.

### 기대 효과

- 현재 글의 전체 구조를 한눈에 볼 수 있습니다.
- 긴 글에서 이동 비용이 낮습니다.
- 독자가 글의 어느 부분을 읽고 있는지 추정하기 쉽습니다.

### 주의할 점

- 본문 폭이 갑자기 줄어들 수 있습니다.
- TOC가 카드처럼 강하면 main content와 경쟁합니다.
- 일반 페이지와 글 상세 페이지의 구조 차이가 커질 수 있습니다.

| 항목 | 장점 | 리스크 |
| --- | --- | --- |
| 오른쪽 TOC | 긴 글 탐색이 빠름 | 3칼럼 전환이 어색할 수 있음 |
| 모달 TOC | 화면 폭을 유지함 | 매번 열어야 함 |
| sticky toolbar | 접근성이 좋음 | 앱 UI처럼 보일 수 있음 |

## Sticky toolbar를 쓰는 방식

Sticky toolbar는 글을 읽는 도중 필요한 도구만 얇게 남기는 방식입니다. 본문 상단을 지나면 작은 bar가 보이고, 그 안에 글 제목과 목차 버튼을 배치할 수 있습니다.

### 기본 형태

```txt
scrolling post detail:
[글 제목..............................][목차]
```

이 구조는 오른쪽 칼럼을 만들지 않으면서도 목차 접근성을 높입니다. 특히 `sidebar + main`의 2칼럼 구조를 유지하고 싶을 때 적합합니다.

### 표시 조건

toolbar는 처음부터 강하게 보이지 않아도 됩니다. 글 헤더가 지나간 뒤 등장하면 본문 집중도를 해치지 않습니다.

구현 방식은 크게 두 가지입니다.

1. CSS `sticky`로 항상 같은 위치에 붙게 만들기
2. `IntersectionObserver`로 헤더가 사라진 뒤 표시하기

### 간단한 관찰 코드

```tsx
const observer = new IntersectionObserver(([entry]) => {
  setVisible(entry?.isIntersecting === false)
})
```

실제 구현에서는 focus 이동, reduced motion, hydration 타이밍도 함께 확인해야 합니다.

## Modal TOC를 쓰는 방식

모달은 작은 화면에서 가장 안정적인 목차 패턴입니다. 사용자가 원할 때만 열리고, 닫으면 다시 본문에 집중할 수 있습니다.

### 모달이 잘 맞는 상황

- 화면 폭이 좁아 오른쪽 rail을 둘 수 없을 때
- 목차 항목이 많아 본문 위에 길게 펼치기 부담스러울 때
- toolbar 버튼 하나로 일관된 접근 지점을 제공하고 싶을 때

### 접근성 체크리스트

- [x] `role="dialog"`와 `aria-modal="true"`를 사용합니다.
- [x] 열릴 때 dialog 내부로 focus를 이동합니다.
- [x] `Escape`로 닫을 수 있어야 합니다.
- [x] 닫힌 뒤 trigger button으로 focus를 복귀합니다.
- [ ] 본문 스크롤 잠금 여부는 실제 화면에서 확인합니다.

## 추천 조합

현재 구조에서는 breakpoint에 따라 역할을 나누는 방식이 가장 자연스럽습니다.

### 큰 화면

큰 화면에서는 오른쪽 TOC를 유지하되, 시각적 무게를 낮춥니다.

- width는 220px에서 240px 사이로 제한합니다.
- border와 shadow는 약하게 둡니다.
- 현재 섹션 highlight는 나중 단계로 미룹니다.

### 작은 화면

작은 화면에서는 sticky toolbar와 modal TOC를 조합합니다.

- toolbar 왼쪽에는 글 제목을 한 줄로 표시합니다.
- 오른쪽에는 목차 버튼만 둡니다.
- 버튼은 중앙 modal을 엽니다.

## 결정 기준

TOC 배치의 핵심은 기능 수가 아니라 읽기 흐름입니다. 목차가 독자를 돕는 순간에는 가까이에 있어야 하고, 본문을 방해하는 순간에는 물러나야 합니다.

### 유지할 원칙

- 기본 shell은 단순해야 합니다.
- 글 상세의 도구는 본문보다 약해야 합니다.
- breakpoint마다 다른 해법을 쓰더라도 사용자의 목적은 같아야 합니다.

### 다음 실험

먼저 큰 화면에서 오른쪽 TOC의 breakpoint와 폭을 조정합니다. 그 다음 작은 화면에서 sticky toolbar가 필요한지 확인합니다.

이 순서가 좋은 이유는 큰 화면 정책이 안정되어야 작은 화면의 toolbar가 진짜 필요한지 판단할 수 있기 때문입니다.
